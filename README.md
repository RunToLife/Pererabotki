# Pererabotki — «Переработка»

Веб-сервис для учета часов переработки: график дежурств, таблицы официальных и неофициальных часов, список дежурных и журнал аудита.

- **Стек:** Python 3.8+, Flask, SQLite, Waitress. Интерфейс — обычный HTML/JS без сборки и внешних CDN (работает без интернета).
- **Установка:** одной командой (`install.bat` или `./install.sh`) — скрипт сам ставит всё нужное, настраивает автозапуск и запускает сервис.

## Быстрый старт

**Windows** — двойной щелчок по `install.bat` (или в `cmd`):

```bat
install.bat
```

**Linux / macOS:**

```bash
./install.sh
```

После установки откроется браузер на **http://127.0.0.1:8080**. Сервис запускается автоматически при каждом входе в систему.

Дальше: вкладка **«Дежурные»** → добавьте людей → вкладка **«График дежурств»** → нажмите **+** в нужном дне.

## Установка подробно

### Что делают скрипты установки

1. **Проверяют Python 3.8+.** Если его нет — пытаются поставить сами:
   Windows — через `winget`; Linux — `apt`/`dnf`/`pacman`; macOS — `brew`.
   Если автоматически не получилось, скрипт скажет, что сделать вручную.
2. **Создают виртуальное окружение** `venv/` в папке проекта (системный Python не затрагивается).
3. **Ставят зависимости** из `requirements.txt` (Flask, Waitress).
4. **Включают автозапуск** (см. таблицу).
5. **Запускают сервис** и проверяют, что он отвечает, затем открывают браузер.

| ОС | Механизм автозапуска | Когда стартует |
|---|---|---|
| Windows | Планировщик заданий, задача `Pererabotki` (без окна консоли, через `pythonw.exe`) | при входе пользователя в Windows |
| Linux | `systemd --user`, юнит `~/.config/systemd/user/pererabotki.service` | при загрузке (после `loginctl enable-linger`) / при входе |
| Linux без systemd | `cron @reboot` | при загрузке |
| macOS | `launchd`, `~/Library/LaunchAgents/ru.pererabotki.plist` | при входе пользователя |

Если на машине нет ни systemd, ни launchd, ни cron, скрипт предупредит об этом: сервис запустится сейчас, а после перезагрузки его нужно будет запускать вручную (`./start.sh`).

### Параметры установки

```bash
./install.sh --no-autostart          # только установить, без автозапуска и без запуска
PERER_PORT=9000 ./install.sh         # другой порт
```

```bat
install.bat --no-autostart
set PERER_PORT=9000 & install.bat
```

### Ручной запуск

```bash
./start.sh        # Linux / macOS
start.bat         # Windows
```

### Установка без скриптов

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt      # Windows: venv\Scripts\pip
venv/bin/python app/server.py                 # Windows: venv\Scripts\python app\server.py
```

### Обновление

```bash
git pull
./install.sh        # переустановит зависимости и перезапустит сервис
```

На Windows — `git pull`, затем `install.bat`. Перезапуск выполняется автоматически для Windows, systemd и launchd; при автозапуске через cron после обновления перезапустите сервис вручную (завершите процесс `app/server.py` и выполните `./start.sh` или перезагрузите компьютер).

База данных лежит в `data/` и при обновлении не затрагивается.

## Как пользоваться

В верхней части страницы всегда видно, под какой учётной записью вы работаете.

### График дежурств

- Календарь текущего месяца (неделя с понедельника, выходные подсвечены, сегодня выделен).
- **+** в ячейке дня — назначить дежурного (можно добавить примечание, например «ночная смена»). В один день можно назначить нескольких, но одного человека — только один раз.
- **×** на плашке — снять дежурного с этого дня.
- Под календарём — сколько дежурств у каждого сотрудника за месяц.
- **Прошлые месяцы:** кнопки **‹ ›**, поле выбора месяца или список «Месяцы с данными…». Прошлые месяцы можно и редактировать — все правки попадают в аудит.

### Официальные часы / Неофициальные часы

Две независимые таблицы с одинаковым интерфейсом:

- Форма сверху: дата, сотрудник, часы (от 0,25 до 24, шаг 0,25), комментарий → **Добавить**.
- В таблице: **Изменить** и **Удалить** для каждой записи, видно, кто внёс запись.
- Внизу таблицы — итог за выбранный месяц.
- Блок **«Сводка по сотрудникам»** показывает за месяц официальные, неофициальные и общую сумму часов по каждому человеку.

### Дежурные

- Форма «Добавить дежурного»: ФИО и должность (оба поля обязательны). Дубликаты по ФИО (без учёта регистра) не принимаются.
- **Изменить** — правка ФИО и должности.
- **Удалить** — человек пропадает из списков и выпадающих меню. Что происходит при удалении:
  - **будущие** дежурства (с сегодняшнего дня) снимаются, каждое снятие записывается в аудит;
  - **прошлые** дежурства и все часы **сохраняются**, ФИО остаётся в истории и отчётах;
  - запись в базе помечается как неактивная, а не стирается.

### Аудит

Журнал всех изменений. Для каждого события хранится:

- **Когда** — дата и время;
- **Кто** — учётная запись и IP-адрес;
- **Действие** — создание / изменение / удаление;
- **Где** — раздел (Список дежурных, График дежурств, Официальные часы, Неофициальные часы);
- **Что и на что** — текстовое описание и поля «было → стало» (для изменений — только изменившиеся поля).

Фильтры: по разделу, по автору, по тексту описания. Журнал подгружается по 50 записей («Показать ещё»). Изменить или удалить записи аудита через интерфейс или API нельзя.

## Как определяется имя пользователя

Браузер не может узнать имя учётной записи ОС компьютера, с которого открыта страница, поэтому имя определяется на стороне сервера. Порядок такой:

| № | Условие | Источник имени | Метка в шапке |
|---|---|---|---|
| 1 | Включено `PERER_TRUST_PROXY=1` и пришёл заголовок `X-Remote-User` (или `REMOTE_USER`) | Имя от обратного прокси со Single Sign-On (например, IIS/nginx с Kerberos/NTLM) | вход через прокси (SSO) |
| 2 | Подключение с самого сервера (`127.0.0.1`/`::1`) | Учётная запись ОС, под которой работает человек за этим компьютером | учётная запись ОС |
| 3 | Подключение с другого компьютера без SSO | Имя, которое человек один раз вводит сам (хранится в cookie) | введено вручную |
| 4 | Ничего из перечисленного | `unknown@<IP>` и запрос имени при открытии страницы | не определено |

**Важно:** автоматически определить учётку ОС удалённого компьютера без SSO невозможно — это ограничение браузеров, а не сервиса. Если сервис используется несколькими людьми по сети, для надёжного аудита настройте SSO через прокси (п. 1). Имена из п. 3 вводятся вручную и могут быть неточными.

Заголовок `X-Remote-User` по умолчанию **игнорируется**: иначе любой мог бы подставить чужое имя. Включайте `PERER_TRUST_PROXY=1` только если сервис доступен исключительно через ваш прокси.

## Настройка

Через переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PERER_HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — доступ из сети |
| `PERER_PORT` | `8080` | Порт |
| `PERER_DATA_DIR` | `<проект>/data` | Где хранить базу и лог |
| `PERER_TRUST_PROXY` | выкл. | `1` — доверять заголовку `X-Remote-User` |

Для автозапуска значения `PERER_HOST` и `PERER_PORT` фиксируются в момент установки. Чтобы поменять их позже — переустановите: `PERER_PORT=9000 ./install.sh` (Windows: `set PERER_PORT=9000 & install.bat`).

## Данные, резервные копии, удаление

- **База:** `data/pererabotki.db` (SQLite). **Лог сервера:** `data/server.log` (ротация, до 4 файлов по 1 МБ).
- **Резервная копия:** остановите сервис и скопируйте `data/pererabotki.db`. Либо на работающем сервисе: `sqlite3 data/pererabotki.db ".backup 'backup.db'"`.
- **Восстановление:** остановите сервис и подложите файл базы на место `data/pererabotki.db`.
- Папка `data/` исключена из git (`.gitignore`) — данные в репозиторий не попадают.

### Остановка и удаление автозапуска

| ОС | Команды |
|---|---|
| Windows | `schtasks /Delete /TN "Pererabotki" /F`, затем завершить процесс `pythonw.exe` (Диспетчер задач) |
| Linux (systemd) | `systemctl --user disable --now pererabotki.service` и удалить `~/.config/systemd/user/pererabotki.service` |
| Linux (cron) | `crontab -e` и удалить строку, оканчивающуюся на `# pererabotki` |
| macOS | `launchctl unload ~/Library/LaunchAgents/ru.pererabotki.plist` и удалить этот файл |

После этого можно удалить папку проекта (вместе с `data/`, если база не нужна).

## Доступ с других компьютеров

По умолчанию сервис слушает только `127.0.0.1` — то есть доступен только на том компьютере, где запущен. Чтобы открыть его для коллег:

1. Установите с `PERER_HOST=0.0.0.0` (Windows: `set PERER_HOST=0.0.0.0 & install.bat`).
2. Откройте порт в брандмауэре.
3. Коллеги заходят на `http://<адрес-сервера>:8080`.

**Безопасность.** В сервисе нет паролей и ролей: любой, кто достучался до порта, может читать и менять данные. Открывайте доступ только во внутренней сети, а для надёжной идентификации в аудите используйте SSO через прокси (см. [выше](#как-определяется-имя-пользователя)). Для доступа из интернета нужен HTTPS-прокси с аутентификацией.

## HTTP API

Все ответы — JSON. Ошибки: `{"error": "текст"}` с кодом 4xx.

| Метод и путь | Назначение |
|---|---|
| `GET /api/me` | Текущий пользователь: `{user, source}` |
| `POST /api/me` | Задать имя вручную: `{name}` |
| `GET /api/employees[?all=1]` | Список дежурных (`all=1` — включая удалённых) |
| `POST /api/employees` | Добавить: `{full_name, position}` |
| `PUT /api/employees/<id>` | Изменить: `{full_name, position}` |
| `DELETE /api/employees/<id>` | Удалить (мягко, снимает будущие дежурства) |
| `GET /api/duties?month=ГГГГ-ММ` | Дежурства за месяц |
| `POST /api/duties` | Назначить: `{date, employee_id, note}` |
| `DELETE /api/duties/<id>` | Снять дежурство |
| `GET /api/hours/<kind>?month=ГГГГ-ММ[&employee_id=N]` | Часы за месяц; `kind` = `official` или `unofficial` |
| `POST /api/hours/<kind>` | Добавить: `{date, employee_id, hours, comment}` |
| `PUT /api/hours/<kind>/<id>` | Изменить (те же поля) |
| `DELETE /api/hours/<kind>/<id>` | Удалить |
| `GET /api/hours/summary?month=ГГГГ-ММ` | Сводка по сотрудникам: официальные / неофициальные / всего |
| `GET /api/months` | Месяцы, за которые есть данные |
| `GET /api/audit?entity=&actor=&q=&limit=&offset=` | Журнал аудита (новые сверху) |

Даты — `ГГГГ-ММ-ДД`. Часы — число больше 0 и не больше 24.

## Внесённые изменения

Репозиторий содержал только заглушку README и служебный каталог `widgets/`. Добавлено:

**Бэкенд (`app/server.py`)**
- REST API на Flask с хранилищем SQLite; таблицы создаются автоматически при первом запуске.
- Определение имени пользователя ОС (4 уровня, см. выше), защита от подмены `X-Remote-User`.
- Дежурные с ФИО и должностью: добавление, правка, мягкое удаление; проверка дубликатов ФИО (с учётом кириллицы и регистра).
- График дежурств по месяцам; защита от повторного назначения одного человека на один день.
- Два отдельных учёта часов — официальные и неофициальные; валидация даты и количества часов; сводка по сотрудникам.
- Аудит: каждое создание/изменение/удаление записывает автора, IP, раздел, описание и значения «было → стало»; правка без реальных изменений в журнал не попадает.
- Запуск через Waitress (кроссплатформенный production-сервер), ротируемый лог.

**Интерфейс (`app/static/`)**
- Пять вкладок: График дежурств, Официальные часы, Неофициальные часы, Дежурные, Аудит.
- Календарь месяца с навигацией по прошлым и будущим месяцам; светлая и тёмная тема по настройке системы; адаптация под узкие экраны.
- Экранирование всего пользовательского ввода (защита от внедрения HTML/JS).

**Установка и запуск**
- `install.bat`, `install.sh` — автоустановка, автозапуск, проверка запуска; `start.bat`, `start.sh` — ручной запуск.
- `.gitattributes` — окончания строк (`.bat` — CRLF, `.sh` — LF); `.gitignore` — `venv/`, `data/`, `*.log`.

**Тесты**
- 13 автотестов API (`tests/test_app.py`).

## Известные ограничения

- Нет паролей и разграничения прав (см. [Доступ с других компьютеров](#доступ-с-других-компьютеров)).
- Имя пользователя ОС автоматически определяется только при подключении с самого сервера или через SSO-прокси.
- Нет выгрузки в Excel/PDF и итоговых отчётов за период длиннее месяца.
- Часы не привязаны к дежурствам автоматически — вносятся отдельно.
- Записи аудита нельзя удалить через сервис, но тот, у кого есть доступ к файлу `data/pererabotki.db`, может изменить его напрямую.
